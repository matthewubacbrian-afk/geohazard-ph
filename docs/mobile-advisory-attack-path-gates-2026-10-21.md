It is an evidence handoff, not a release security signoff. A vulnerable installed version, an observed library call, and a reachable attack path are different claims. All 34 rows in that dated report were **undetermined**.

**2026-10-24 update:** The [PR #66 image-input trace](mobile-image-input-trace-2026-10-24.md) returned 12 live audit rows on each platform, all `undetermined`, with no lockfile change. GitHub withdrew the [`sprintf-js` advisory](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) on October 22 and the [`braces` advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) on October 23. Those two rows and their inherited chains are absent from the current audit, not newly classified as safe. The historical source reviews below remain useful if either advisory is reinstated. The three still-reported directly affected packages are `fast-xml-parser`, `image-size`, and `node-forge`, carrying four direct references. PR #66 merged at `c398d31c` after five exact-head checks and final Android/iOS report comparison; only the Android APK hash differed beyond the approved audit-feed change.

## Verified inventory and limits

Both final PR #61 reports contain 34 production dependency-chain findings: 28 high and six moderate, with zero critical. Five directly affected installed packages carry six GitHub advisory references; the other 29 report rows inherit a vulnerable-package link. The Android and iOS advisory identities and dispositions match; their `react-native` source-map entry counts differ by platform (404 and 400). Each map lists 25 package names. None of the five directly affected package names has a source-map match. Android lists 196 selected `.so` entries, and iOS lists the app and Hermes executables. The reports do not trace Node build processes, Android DEX, statically linked native code, or calls within the device app. An absent package-name match cannot classify a finding as build-only.

The rows below use the exact installed versions from `mobile/package-lock.json`. “Observed” means the cited published source contains the stated call or boundary; it does not mean the call was captured during a PR #61 build. The `braces` and `sprintf-js` rows describe withdrawn, historical references rather than current audit findings.

For any disposition change, establish the full chain: a reachable entry point, who can control the required input, the affected operation at the installed version, the process in which it runs, and the effect under that process's error or timeout handling. For device attribution, inspect the actual bundled/native execution path rather than inferring it from package-name lists. Repeat audit identities, package versions, and Release evidence after the supported React Native migration; the current reports describe 0.75.5 only.

The asset-provenance checkpoint narrows the current local Metro input inventory but leaves externally supplied or generated input paths open. The [PR #64 Release build-process trace](mobile-build-process-trace-2026-10-21.md) observed a Metro build on both platforms: `braces` and `image-size` files loaded without recorded named calls, XML parsing and validation functions ran but no named XML builder call was recorded, and `node-forge` and `sprintf-js` files were not recorded as loaded in the scoped commands. The later [PR #66 image-input trace](mobile-image-input-trace-2026-10-24.md) recorded two `image-size` module loads and zero parser calls per platform across its covered Release Node threads. These observations do not establish input control, affected-operation arguments in other builds, device inclusion, or a disposition change. The next active advisory review is the remaining `fast-xml-parser` builder-consumer path; generated/external image inputs and `node-forge` caller provenance remain open. The source and domain approval, physical-device, and held-profile export gates in [PLAN.md](../PLAN.md) remain independent.
