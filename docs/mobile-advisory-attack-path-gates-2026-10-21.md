# Mobile advisory attack-path gates — 2026-10-21

This record reconciles the five [bounded consumer-call reviews](mobile-advisory-exposure-review-2026-10-20.md) with the final non-published Android/iOS Release reports from [PR #61](https://github.com/matthewubacbrian-afk/geohazard-ph/pull/61). It is an evidence handoff, not a release security signoff. A vulnerable installed version, an observed library call, and a reachable attack path are different claims. All 34 audit finding dispositions remain **undetermined**.

## Verified inventory and limits

Both final PR #61 reports contain 34 production dependency-chain findings: 28 high and six moderate, with zero critical. Five directly affected installed packages carry six GitHub advisory references; the other 29 report rows inherit a vulnerable-package link. The Android and iOS advisory identities and dispositions match; their `react-native` source-map entry counts differ by platform (404 and 400). Each map lists 25 package names. None of the five directly affected package names has a source-map match. Android lists 196 selected `.so` entries, and iOS lists the app and Hermes executables. The reports do not trace Node build processes, Android DEX, statically linked native code, or calls within the device app. An absent package-name match cannot classify a finding as build-only.

The rows below use the exact installed versions from `mobile/package-lock.json`. “Observed” means the cited published source contains the stated call or boundary; it does not mean the call was captured during a PR #61 build.

For any disposition change, establish the full chain: a reachable entry point, who can control the required input, the affected operation at the installed version, the process in which it runs, and the effect under that process's error or timeout handling. For device attribution, inspect the actual bundled/native execution path rather than inferring it from package-name lists. Repeat audit identities, package versions, and Release evidence after the supported React Native migration; the current reports describe 0.75.5 only.

The next evidence priority is asset provenance for both `image-size` advisories because the inspected Metro path can dispatch by file bytes despite its filename gate. This is a choice of investigation order, not a claim of attacker control or greater exploitability. A separate build-process observation could then test whether any of the five packages actually loads or calls affected APIs during non-published CI builds. The source and domain approval, physical-device, and held-profile export gates in [PLAN.md](../PLAN.md) remain independent.
