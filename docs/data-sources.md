# Data Sources

## Earthquakes

- USGS Earthquake Catalog: REST/GeoJSON, no API key.
  - The ingestion worker polls the USGS Earthquakes feed (`/fdsnws/event/1/query`) filtered to the Philippines bounding box and `eventtype=earthquake`, then upserts records into Postgres.
  - The bounding box comes from the `PH_BBOX` config (default `116.0,4.0,128.0,22.0`; west, south, east, north).
  - Poll cadence stays at or above one minute to respect USGS feed caching.
  - Attribution: USGS data requires attribution to the "USGS Earthquake Hazards Program". Display the source and last-updated time alongside any USGS-derived view.
- PHIVOLCS earthquake bulletins: scraped source, no official public API assumed.

Canonical matching retains source rows separately and groups only pairwise-compatible,
cross-source reports. Corrections to a row with a stable `external_id` update that
row and trigger regrouping. When a source supplies no `external_id`, the content
key changes with time, coordinates, or magnitude; inspect such apparent revisions
before treating them as the same event. See ADR 0003 and the reconciliation runbook.

## Kaggle Historical Earthquake Datasets

The ML risk profiling pipeline uses two Kaggle datasets:

- `bwandowando/philippine-earthquakes-from-phivolcs` — PHIVOLCS earthquake records, CC0: Public Domain
- `bwandowando/philippine-earthquakes-1900-2025-from-usgs` — USGS earthquake records for the Philippines, Apache 2.0

Access requires a Kaggle account and API key (`KAGGLE_USERNAME` and `KAGGLE_KEY` environment variables, or `~/.kaggle/kaggle.json`).

By default, each training run uses `kagglehub.dataset_download` to resolve the latest
version of each dataset with `force_download=True`. The download replaces the raw
dataset tree under `ml/data/raw/<owner_slug>/` (the dataset handle with `/` replaced
by `_`), so its files match the resolved version rather than retaining files from
an older version.

The artifact's `metadata.json` records each resolved version as an integer in
`datasets[].version`. To reuse saved CSVs without downloading, use `--offline`
with repeatable `--phivolcs-csv` and `--usgs-csv` paths in the Python CLI, or
`-Offline` with `-PhivolcsCsv` and `-UsgsCsv` path arrays in the PowerShell
wrapper. Both source groups are required. The command rejects missing,
non-CSV, or duplicate paths before training, because source assignment controls
timestamp normalization and deduplication. Programmatic callers can use
`ml.train.run_training(download=False, phivolcs_paths=[...], usgs_paths=[...])`.

Offline runs record `datasets[].version` as `null` because they do not resolve
a Kaggle version. Both training modes record each input CSV's source, filename,
byte count, and SHA-256 digest in `metadata.json.input_files`. The digest
identifies exact file contents without exposing local absolute paths. Preserve
the matching raw CSVs when a retrain must be reproduced.

The saved PHIVOLCS snapshot uses `Date_Time_PH` and `Depth_In_Km`; those fields
are parsed as Manila time and kilometers. The saved USGS snapshot is parsed as
UTC. Both sources are deduplicated, then assigned by epicenter to the pinned
17-region web boundary asset. Events outside a polygon join its nearest region
only when the distance to that boundary is at most 100 km. More distant or
invalid-coordinate events are excluded. `metadata.json.region_assignment`
records the boundary asset SHA-256, distance limit, and assigned/excluded
counts by source after deduplication. `source_reports` counts parsed/rejected
rows before deduplication.

The 2026-10-14 local offline run parsed 142,493 PHIVOLCS and 26,483 USGS rows;
after deduplication and the distance rule, it assigned 134,335 and 21,402
events respectively. It generated 17 region names matching the web asset. The
source files lack a recorded Kaggle version, so their exact input hashes are
the reproducible identifiers. These profiles are descriptive statistics; the
classifier's training-set accuracy is not an independent quality estimate.
The offline `ml.validate_profiles` command checks those hashes and the pinned
boundary hash, reproduces parser and assignment totals, and reports each
region's PHIVOLCS and USGS date spans and counts. Its shared-window comparison
aligns dates only; it does not equalize magnitude thresholds, completeness,
exposure, or catalog quality. Seed and leave-one-region-out comparisons measure
label sensitivity, not predictive accuracy. Generated reports stay ignored and
always require domain review before an export can be considered for staging.

**Attribution:** Data sourced from Kaggle contributors who aggregated public PHIVOLCS and USGS records. Original data is public domain (PHIVOLCS) or open license (USGS). The risk labels generated by this pipeline are statistical profiles, not predictions.

## Static Layers

- GEM Global Active Faults Database: fault-line reference data.
- PHIVOLCS Active Fault Atlas: manual or semi-manual digitization source.
- NASA Global Landslide Susceptibility Map: remote global raster reference, approximately
  1 km pixel size, with service values from 0 to 5. Credit NASA and link the map/service
  in the UI. Label it as a **coarse, informational susceptibility reference**; NASA
  warns it may be research-grade and unsuitable for operational use. It is an
  awareness aid, not an early-warning authority, live warning, event probability, or
  site-level assessment. Do not interpret missing pixels as low susceptibility. The
  dashboard requests imagery from the [NASA ImageServer](https://gis.earthdata.nasa.gov/portal/rest/services/Landslides/Global_Landslide_Susceptibility/ImageServer)
  at runtime; the raster is not copied into project storage.
- MGB detailed rainfall-induced landslide susceptibility polygons may be considered as
  a separate higher-resolution reference after reuse rights and geographic coverage
  are confirmed. Public service access alone does not establish those terms; do not
  copy or display the polygons until reviewed. A future MGB layer can complement the
  NASA global reference.
- InSAR deformation datasets: future feasibility work; validate source terms, coverage,
  revisit cadence, processing requirements, and operational limits before use.
- Epic 6 Part 2 InSAR desk review (2026-10-16): NISAR L-band is the recommended
  longer-wavelength candidate for comparison in a bounded research pilot. A
  University of the Philippines Diliman Philippine Engineering Journal article
  reports a Sentinel-1 persistent-scatterer InSAR study in Antipolo, 184,253
  persistent-scatterer points, and LOS displacement correlation of 0.83 against a
  stationary GNSS receiver. Its acquisition details, footprint, and underlying GNSS
  series must be reviewed before treating the paper as a reproducible validation
  benchmark. NISAR launched after that study, so it cannot reproduce that historical
  observation period; it requires a current independent ground reference for any
  direct comparison.
  ASF currently describes NISAR PROVISIONAL products as calibrated and partially
  validated; each site's actual track/frame coverage, maturity, temporal sampling,
  quality, latency, and product availability must be checked in the archive. The
  recommendation is not evidence that any Philippine landslide site has usable
  acquisitions or validated motion. Sentinel-1 on-demand InSAR is available through
  ASF HyP3, subject to SLC-pair selection, Earthdata authentication, monthly Basic
  credits/queue limits, and temporary product retention. InSAR can be affected by
  decorrelation, atmosphere, DEM/orbit residuals, geometry, and unwrapping; do not
  draw conclusions from one pair. Any later display must label LOS displacement as
  research-grade and informational, show acquisition dates and quality gaps, and
  must not present it as an early warning, forecast, or safety determination.
  Credit NASA/ISRO and ASF for NISAR products, and ESA/Copernicus Sentinel-1 and ASF
  for Sentinel-1 products according to the product citation and terms. See the
  [Epic 6 InSAR feasibility spec](superpowers/specs/2026-10-16-epic6-insar-feasibility-design.md)
  and its primary-source links before any pilot or product work. A read-only ASF
  metadata query on 2026-10-16 found 34 descending Sentinel-1B IW SLC records
  (relative orbit 61) and 26 PROVISIONAL NISAR GUNW records intersecting only the
  published Naga landslide event-centroid point. This does not establish coverage
  of the source scarp or usable pixel quality. No scenes were downloaded, no HyP3
  jobs were submitted, and no displacement was measured. The screening details and
  reproducible catalog links are in the
  [Epic 6 InSAR pilot report](epic6-insar-pilot-report.md).
- Philippine administrative regions: the version-pinned geoBoundaries open ADM1
  derivative for the Philippines, sourced from NAMRIA, PSA, and OCHA Philippines.
  The web risk overlay uses the simplified WGS84 FeatureCollection from boundary
  `PHL-ADM1-36201628`, represented in 2020 and built July 5, 2023. License:
  Creative Commons Attribution 3.0 Intergovernmental Organisations (CC BY 3.0 IGO).
  Source: https://www.geoboundaries.org/api/current/gbOpen/PHL/ADM1/.
  The derived file is `web/src/data/philippine-regions.json`, simplified and quantized

  `shapeName` field. The overlay also maps province-level `Palawan` profiles to the
  `Mimaropa` ADM1 boundary. Unmapped names are omitted rather than assigned guessed geometry.
  The checked-in asset must stay under 1.5 MB raw and 300 KB gzipped, enforced by

## Attribution

Every client view that displays public hazard data should identify source and last-updated time. PHIVOLCS-derived scraped data should be labeled as unofficial aggregation and linked back to the source.

### PHIVOLCS volcano listing adapter

The Epic 2 adapter reads the [PHIVOLCS WOVODAT listing](https://wovodat.phivolcs.dost.gov.ph/bulletin/list-of-bulletin).
It extracts the published alert ticker (`span.scroll-item`) and the English
`/bulletin/activity-*` links/headings, selecting the latest observation per volcano.
Alert ticker values are separate from bulletin observation times: a date is not
evidence of when an alert level changed. Missing bulletin dates remain null.
No coordinates are inferred from the volcano name, and no alert is inferred from
seismic data. This is an unofficial aggregation linking back to PHIVOLCS.

`backend/tests/fixtures/phivolcs_volcano.html` is a reduced structural excerpt
captured on 2026-09-08, retaining the source's ticker and four English bulletin
links. Navigation, scripts, images and unrelated content were removed.
The local certificate-chain check failed during capture; the excerpt was inspected
with verification bypassed solely for parser development. Runtime fetching always
verifies TLS. The fixture is historical test input, never a fallback feed or a
claim about current alert status. Levels, source links and Manila-to-UTC conversion
are covered by deterministic tests.
